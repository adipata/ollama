Pod management is disabled. The proxy runs in external mode (VLLM_BASE_URL is set), so it uses that vLLM server as it is. Remove the variable and restart the proxy to connect and deploy to a Runpod pod from here.

Connection

How to start the pod in the Runpod console
  • Template Ubuntu 24.04 (runpod/base:2.1.0-cuda1320-ubuntu2404), no network volume.
  • Container disk: model size + 25 GB. Use 100 GB if either variant of the default profile should work.
  • Expose only TCP port 22 and remove the HTTP ports: the image's JupyterLab, nginx and web terminal are not needed.
  • Your public SSH key on the Runpod account.
  • Then copy the command under Connect → SSH over exposed TCP and paste it below, unchanged.

Confirm the pod's host key

The pod presents a different key than the one confirmed before. That is expected after the pod was restarted; otherwise do not continue.

Fingerprint presented by :

Compare it with the output of ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub in the pod's Runpod web terminal. Nothing has been sent to the pod yet; the key is asked for once per pod start.

This pod is billed until you terminate it in the Runpod console. Stopping vLLM or disconnecting here does not stop the billing, and the application cannot terminate the pod for you.

Hugging Face token

One token for all downloads; needed only for gated or private repositories. It is stored by the proxy, passed to the pod as HF_TOKEN at deploy time and never shown again.
